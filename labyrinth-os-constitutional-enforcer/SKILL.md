## Instructions
Apply this enforcer to every proposal or action that could impact state, external systems, financial outcomes, knowledge integrity, consciousness interfaces, or has non-trivial resource/side-effect footprint. Never bypass the gate.

### 1. Epistemic Lane (Reasoning & Proposal Phase)
- Fully articulate the proposal including intended outcomes, affected objectives, resource costs, risks, and assumptions.
- Simulate downstream effects across all three core objectives using multi-tier reasoning (default Haiku; escalate to Sonnet/Opus per complexity).
- Log all assumptions explicitly with falsification criteria (inspired by ACP-1 pattern: Verified / Partial / Open status).
- Run internal consistency checks, relevant tests, or lightweight formal methods where applicable.
- Emit preliminary A2A evt- record of type "proposal_epistemic" with full context.
- Prepare scored self-assessment against the five Sigma Anchors (see references/labyrinth-os-core-concepts.md for detailed definitions and adaptation rationale).

### 2. Cross L09 Reality Gate (Mandatory Single Crossing Point)
- Evaluate the proposal against all five adapted Sigma Anchors using rigorous checklist + confidence scoring:
  1. Objective Alignment & VPD Anchor (Sigma-01)
  2. Consciousness Integrity & No-Harm Anchor (Sigma-02)
  3. Verifiability, Truth & Assumption Tracking Anchor (Sigma-03)
  4. Thermodynamic, Sovereign & Sustainability Anchor (Sigma-04)
  5. Risk, Maru & Trace-Consent Anchor (Sigma-05)
- Use formal verification mindset (Z3-style where propositions are formalizable). Any anchor below threshold, high uncertainty, or unresolved assumption -> immediate gate failure.
- No exceptions, overrides, or soft bypasses permitted under any circumstances.
- Record gate decision with per-anchor scores, evidence, and reasoning in immutable trace-consent ledger.

### 3. Execution Lane (Only on Full Gate Pass)
- Proceed with the approved action (tool invocation, file edit, external call, decision commit, code generation, etc.).
- Maintain full observability: emit detailed A2A JSONL evt- record of type "proposal_executed" including utilization metrics, VPD attribution, and objective impact projections.
- Credit orchestration hubs and Diamondnode portfolio with appropriate multipliers per QUBO economics.

### 4. Failure Path & Bounded Healing Loop (On Gate Failure)
- Emit typed FailedProposal record with failure codes mapped to specific anchors and evidence gaps.
- Archive to immutable ledger with full provenance.
- Enter bounded healing loop (max iterations tracked and capped):
  - Unconditional maru reframe: surface hidden assumptions, reframe from first principles aligned to core objectives.
  - Gather missing data, evidence, or external attestation as required.
  - Re-propose refined version or escalate: higher Hermes tier (Sonnet/Opus), maru specialist, or human-in-the-loop for existential/consciousness-critical cases.
- Never allow infinite loops or persistence of un-gated proposals.
